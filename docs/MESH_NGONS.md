# Editable mesh n-gons

Contract: Meshes polygon/base hair-shell faces may contain three or more distinct valid vertex indices. Existing face arrays remain the authored source of truth, with no new schema or preference. Existing meshes are unchanged until edited. Bevel preserves its surrounding polygons instead of forcing quad transition cuts; its preview uses the same triangulator as rendering. OBJ retains authored polygons. Triangle-to-face IDs keep picking on one authored face, while wire display uses its perimeter. Undo, mirroring, duplication and project restoration retain the existing face arrays; groups and presets add no new parameters. Quad-specific loop-cut and procedural face tools stop at unsupported faces rather than truncating them. Acceptance: concave/reversed n-gon triangulation, boundary metadata, bevel, OBJ, undo/restoration and baseline tests. Nonplanar faces are projected for triangulation; self-intersecting polygons are not supported.

Verified in an isolated production app: single-edge bevel gives 7 faces (previously 10); six-segment chain 32, three-way 63, loop 30, all-edge cube 222. Finite render attributes, exported polygon arities, undo/redo, preview cancellation and JSON snapshot/restoration passed. Concave triangulation, perimeter counts and face IDs are covered by module tests. Native picking appearance, linked mirrors, on-disk save dialogs and downstream import remain user-led; the working scene was untouched. Older builds with quad-only validation should not be used to reopen newly authored n-gon projects.
